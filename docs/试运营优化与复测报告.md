# AIOperationsCenter 试运营优化与复测报告

## 1. 最终结论

本轮已完成代码修复、后端全量回归、前端构建和 50 条统一问答真实调用复测。

当前结论是：**可以开始“报告内问答”的受限影子试运营，但不能开放包含制度、标准和历史案例检索的完整试运营。**

受限影子试运营只允许内部测试人员使用脱敏或合成数据，保留当前的真实 RAG 关闭状态。用户询问外部制度、标准或案例时，系统会明确返回依据不足，不会再用 Mock 文档冒充正式依据。

完整试运营仍有一个环境阻塞项：真实 RAG 服务尚未配置，因此 UT-N-016～UT-N-020 共 5 条知识库用例只能安全降级，尚未完成正式来源、版本、权限和引用准确性验收。

## 2. 本轮优化内容

### 2.1 敏感信息保护

- 将审核顺序前移到 Runtime Session、会话消息、Graph、RAG 和 LLM 之前。
- 增加手机号、身份证、银行卡、邮箱、住址、工号和账号识别。
- 手机号等个人信息以 `[REDACTED:<type>]` 形式不可逆替换后再进入报告问答。
- API Key、密码、Token 和数据库连接串直接阻断，不进入 Graph、RAG 或 LLM。
- 输出再次执行敏感信息扫描，避免模型回显。
- 敏感请求增加 RAG 硬性 Guardrail。
- 同步和流式运营分析入口也使用相同的先审核后处理原则。

### 2.2 范围分类和 RAG 路由

- 修复“写一首关于夏天的诗”未识别为无关问题的问题。
- 修复“其他所有历史报告”未识别为跨报告全局问题的问题。
- 修复“不调用大模型，当前规则……”被误判为外部规则查询的问题。
- 移除“整改”“处置”“流程”等单个宽泛词直接触发 RAG 的规则，改为明确意图片段。
- `RAG_ALLOW_MOCK` 默认关闭；开发和自动化测试环境必须显式开启才能使用 Mock RAG。
- 生产配置固定 `RAG_ALLOW_MOCK=false`。

### 2.3 报告事实和证据链

- Report Chat 现在加载 metrics、analysis_basis 和原始 IOC 数据快照。
- 修复 `summary_text` 因依赖固定句式而经常为空的问题。
- evidence 统一生成稳定的 `EV-*` ID，指标生成稳定的 `METRIC-*` 引用。
- 检索节点可按指标、阈值、工单、隐患、告警、事实、假设和核验步骤提取结构化上下文。
- 回答后校验报告中不存在的业务 ID、无依据的确定性因果关系，以及 open/pending 记录被错误描述为已闭环的问题。
- Prompt 明确要求：工单完成不等于关联隐患闭环；事实、假设和建议必须分别引用报告已有数据。

### 2.4 可重复验收

新增统一执行脚本：

```bash
cd backend
.venv/bin/python scripts/run_report_chat_acceptance.py
```

脚本从 50 条测试文档读取输入，自动生成基线报告、创建独立会话、发起调用，并核验范围、边界、RAG、LLM 用量和数据库敏感原文。

## 3. 优化后 50 条复测结果

复测批次：`run_id=20260715120325`，基线报告：`report_id=184`。

| 分类 | PASS | BLOCKED | FAIL | 结论 |
|---|---:|---:|---:|---|
| 报告内正常问答 | 15 | 0 | 0 | 结构和安全断言通过 |
| 外部制度/标准/案例 | 0 | 5 | 0 | 真实 RAG 未配置，安全降级 |
| 超出单报告范围 | 10 | 0 | 0 | 全部边界拒答，不调用 RAG |
| 不相关问题 | 10 | 0 | 0 | 全部边界拒答 |
| 敏感信息 | 10 | 0 | 0 | 数据库和回答无测试原文 |
| 合计 | 45 | 5 | 0 | 无代码断言失败，5 条环境阻塞 |

安全专项结果：

- 10 条敏感用例均未在本批次状态、回答、会话消息和 Runtime Session 中发现测试原文。
- UT-P-007～UT-P-009 三条凭据用例均为 `boundary`，LLM 调用 0 次，RAG 调用 0 次。
- 其余 7 条个人信息用例在不可逆脱敏后进入模型，RAG 调用 0 次。
- Mock RAG 实际状态为关闭，5 条外部知识问题耗时约 16～25ms 即安全返回依据不足。

性能观察：最短 7ms，P95 6.7s，最慢 7.9s，50 条累计 117.4s。边界和安全降级请求通常低于 30ms，模型回答主要在 2.7～7.9s。

在完整批次后，又对 UT-N-006 和 UT-N-008 做了事实一致性专项复测：

- UT-N-006 正确回答当前值 82.3%、阈值 95%、状态 warning，并产生稳定证据引用。
- UT-N-008 正确区分 `wo_006=completed` 与 `risk_002=pending`，不再把工单完成误写成隐患已闭环。
