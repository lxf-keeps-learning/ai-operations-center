# 数据库初始化说明

本文档说明 `AIOperationsCenter` Sprint0 本地 MySQL 初始化方式。当前本地开发不依赖 Docker，数据库通过本机 MySQL/Navicat 创建；Docker Compose 仅保留为后续标准部署方式。

## 1. Navicat 创建 ioc_ai 数据库

在 Navicat 中连接本机 MySQL 后：

1. 右键连接，选择“新建数据库”。
2. 数据库名填写 `ioc_ai`。
3. 字符集选择 `utf8mb4`。
4. 排序规则选择 `utf8mb4_unicode_ci`。
5. 确认创建。

可以在 Navicat 查询窗口执行：

```sql
CREATE DATABASE IF NOT EXISTS ioc_ai
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'ioc_user'@'localhost' IDENTIFIED BY 'ioc_password';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX
  ON ioc_ai.* TO 'ioc_user'@'localhost';
FLUSH PRIVILEGES;
```

## 2. 配置 DATABASE_URL

后端只从 `DATABASE_URL` 读取数据库连接。

```bash
cd /Users/lxf/Documents/xinao/AIAgent/AIOperationsCenter/backend
cp .env.example .env
```

确认 `backend/.env` 中包含：

```text
DATABASE_URL=mysql+pymysql://ioc_user:ioc_password@localhost:3306/ioc_ai
```

如果你的 MySQL 端口、用户名或密码不同，只需要修改 `DATABASE_URL`。

MySQL 是当前 Sprint0 必须跑通的主数据库，Demo CRUD 接口会通过 SQLAlchemy 读写 `system_items` 表。

## 3. Redis 本地开发说明

当前本地开发模式 Redis 可不启用。确认 `backend/.env` 中保留：

```text
REDIS_ENABLED=false
REDIS_URL=redis://localhost:6379/0
```

当 `REDIS_ENABLED=false` 时，后端不会在启动时连接 Redis，Redis 未启动也不会影响 MySQL、接口文档或 Demo CRUD。后续标准部署模式可将 `REDIS_ENABLED` 改为 `true` 并配置实际 `REDIS_URL`。

Redis 是后续缓存、会话、任务状态、限流能力的预留组件；Sprint0 只保留配置和健康检查，不引入复杂缓存业务。

健康检查接口：

```bash
curl http://localhost:8000/api/cache/ping
```

默认返回 `Redis disabled`。启用 Redis 后，该接口会尝试连接并返回 `pong`；连接失败时会返回清晰错误信息，不影响其他接口。

## 10. Tool Registry 数据表与初始化

Tool Registry 平台化改造新增四张表（`tool_definitions`、`tool_versions`、`tool_policies`、`tool_call_audits`），由 Alembic 迁移 `20260819_0004` 创建，治理加固迁移 `20260819_0005` 增加操作人、灰度版本比例、策略启用 scope 唯一约束、审计快照与确认令牌单次消费索引。

### 10.1 迁移与内置工具种子

```bash
cd backend
.venv/bin/alembic upgrade head        # 创建 tool_registry 四张表
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/seed_tool_registry.py   # 幂等写入 6 个内置工具
```

种子脚本采用创建式幂等：首次执行时 6 个内置工具初始化为 `1.0.0`、`published + stable` 和默认 allow 策略（每租户每版本每分钟 60 次）；重复执行只补齐完全缺失的层级，不修改已存在定义、版本或策略，因此不会重新启用工具、恢复退役版本或把 deny 改回 allow。

### 10.2 运行模式切换

```bash
# 验证管理 API（/api/v1/tool-registry/*，仅 admin 角色）与审计记录后，切换数据库模式：
TOOL_REGISTRY_MODE=database

# 回滚（无数据损失，立即恢复旧 Registry 直接调用）：
TOOL_REGISTRY_MODE=legacy
```

默认模式仍为 `legacy`。database 模式下 Agent、MCP 与 Tool API 的全部调用都经过 Tool Gateway（权限、限流、灰度、动作确认、审计），MySQL 不可用时按缓存降级（配置缓存 30 秒、查询/分析稳定快照最长 24 小时，动作类工具在普通缓存过期后一律拒绝执行）。

### 10.3 限流语义说明

默认限流为**进程内固定窗口**限流：单实例部署时额度精确，多 worker 部署时每进程各自持有 60 次/分钟额度，全局配额需要在后续引入 Redis 分布式限流实现（本期不启用 Redis，也不通过 MySQL 高频写计数）。
