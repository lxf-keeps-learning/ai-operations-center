# 全站统一主题切换设计

## 背景

当前新版 Agent 控制台使用较深的蓝黑色调，旧版页面使用浅色样式，且颜色主要分散在各布局和页面的硬编码中。需要提供一个全站统一的明亮绚丽主题，并保留深色主题切换能力。

## 目标

- 默认使用明亮绚丽主题。
- 支持在明亮绚丽主题和当前深色主题之间切换。
- 新版 Agent 控制台与旧版页面同步切换，保持统一风格。
- 刷新页面后保留用户上次选择。
- 主题切换不影响路由、业务数据和页面交互。
- 为后续增加主题保留清晰的扩展边界。

## 设计

### 主题状态

新增全局主题状态（复用现有 Pinia 架构），主题标识使用明确的联合类型：

- `vivid-light`：明亮绚丽主题，作为默认值。
- `deep-night`：当前蓝黑深色主题。

初始化时优先读取 `localStorage` 中的主题值；没有值或值无效时使用 `vivid-light`。状态变化时同步更新 `document.documentElement` 的 `data-theme` 属性，并写回 `localStorage`。

### 视觉变量

在全局主题样式中为背景、面板、文字、弱化文字、边框、主色、渐变、阴影和交互态定义 CSS 变量。页面和布局中的主题相关颜色改为引用变量；状态类颜色（成功、警告、错误、信息）保留语义色，但其背景和文字对比度需要适配两种主题。

明亮绚丽主题以浅色背景为基础，使用蓝紫、青绿和粉紫渐变作为品牌高亮、激活态和关键操作反馈；深色主题沿用当前视觉基线，只将分散的颜色收敛到变量，避免切换后出现局部样式失配。

### 切换入口

在新版 `PlatformLayout` 和旧版 `DefaultLayout` 的顶栏操作区提供同一语义的主题切换按钮。按钮显示当前主题名称或可识别图标，并提供 `aria-label` 和 `title`；点击后立即切换，不需要刷新页面。两个布局共用同一个主题状态，因此从任意页面切换都会同步全站。

### 边界与兼容

- 只改主题相关的布局样式和页面颜色，不重构业务组件。
- 主题状态属于客户端偏好，不新增后端接口或数据库字段。
- 通过根元素主题属性覆盖全局样式；组件内的 scoped 样式通过 CSS 变量消费主题值。
- 小屏布局保留现有响应式结构，主题按钮压缩为适合窄屏的操作控件。

## 验证

- 类型检查和生产构建通过。
- 主题状态默认值为 `vivid-light`，无效持久化值可回退默认值。
- 切换主题会更新根元素主题属性并持久化。
- 在新版和旧版路由分别切换，确认两套页面同步变化。
- 刷新页面后主题选择保持。
- 检查桌面与窄屏下主题按钮可见、可操作，且文字与控件具有足够对比度。
