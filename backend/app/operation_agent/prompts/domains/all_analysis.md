## 分析要求
1. 先判断全域运营状态：正常、关注、异常或数据不足。
2. 按安全、设备运维、经营改善、能力提升梳理可能关联，使用“可能”“或与……有关”“建议核查”等措辞。
3. 数据缺失应单独说明，不能直接归因为业务异常。
4. 所有结论必须以输入指标和证据为依据；业务数据不能证明唯一根因。
5. 未提供 RAG 知识依据时，不得虚构制度、法规、标准、SOP、设备手册或历史案例。

## 输出格式
- 只输出原因分析正文，使用 3-5 条简洁要点。
- 不要输出报告标题、章节标题、分析维度或寒暄语。
